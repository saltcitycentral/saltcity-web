# Ebenezer Grant Setup

The feature is built for the existing Next.js App Router site and uses Supabase only from server-side code.

## Required Environment Variables

Set these in `.env.local` and in Vercel:

```txt
NEXT_PUBLIC_SUPABASE_URL=
NEXT_PUBLIC_SUPABASE_ANON_KEY=
SUPABASE_SERVICE_ROLE_KEY=
SUPABASE_STORAGE_BUCKET=
ADMIN_USERNAME=
ADMIN_PASSWORD=
```

Optional email variables:

```txt
RESEND_API_KEY=
RESEND_FROM_EMAIL=
NEXT_PUBLIC_SITE_URL=
```

Email is optional. Missing or failing email configuration does not block application submission.

## Supabase SQL Setup

Before testing, run the SQL in `supabase/ebenezer-grant.sql` inside the Supabase SQL editor for the project.

The SQL creates:

- `grant_applications`
- `grant_documents`
- indexes for reference number, business registration number, status, and application documents
- restrictive RLS policies with no public read/write access

All application writes and admin reads are performed by the Next.js server using `SUPABASE_SERVICE_ROLE_KEY`.

## Storage Bucket

Create or confirm the private Supabase Storage bucket named by:

```txt
SUPABASE_STORAGE_BUCKET
```

Keep the bucket private. Uploaded files are stored under:

```txt
ebenezer-grant/{reference_number}/{timestamp}-{safe-file-name}
```

Admin document access uses short-lived signed URLs generated server-side.

## Testing Application Submission

1. Run the SQL file in Supabase.
2. Confirm the private storage bucket exists.
3. Start the site locally with `npm run dev`.
4. Open `/ebenezer-grant`.
5. Fill all required fields.
6. Upload PDF, JPG, JPEG, PNG, DOC, or DOCX files, each 10MB or smaller.
7. Submit the form.
8. Confirm the on-site receipt shows a reference number like `EBZ-2026-0001`.

The business registration number is unique. Submitting twice with the same registration number should show a friendly duplicate error.

## Admin Dashboard

Open:

```txt
/admin/ebenezer-grant
```

The admin area is protected with HTTP Basic Auth using:

```txt
ADMIN_USERNAME
ADMIN_PASSWORD
```

From the dashboard, open an application to view full details, update status/internal notes, and view/download uploaded documents through signed URLs.

## Deploying On Vercel

1. Add all required environment variables to the Vercel project.
2. Run the SQL in the production Supabase project.
3. Confirm the private storage bucket exists in production.
4. Deploy the current branch.
5. Test `/ebenezer-grant` and `/admin/ebenezer-grant` after deployment.

## Security Notes

Never expose `SUPABASE_SERVICE_ROLE_KEY` in frontend code. It must only be used in server routes, server components, or server-only helpers.

Do not make the storage bucket public. Documents should only be accessed with signed URLs generated by protected server-side admin routes.
